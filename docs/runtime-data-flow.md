# FleetAvail runtime data flow\n\n## End-to-end flow\n\n```\nC-MAPSS / incoming telemetry\n        |\n        v\nPOST /api/predict OR WS /ws/telemetry\n        |\n        v\nCMapssModelRuntime\n        |\n        +--> normalize raw telemetry\n        +--> bounded 30-cycle ENGINE history\n        +--> clean + temporal features (delta / MA5 / MA10 / MA20)\n        +--> training-time scaler\n        |\n        +-------------------+----------------------+------------------+\n        |                   |                      |\n        v                   v                      v\n    LSTM / TCN         XGBoost failure       Isolation Forest\n       RUL               probability           anomaly score\n        |                   |                      |\n        +-------------------+----------------------+\n                            |\n                            v\n                     Health Fusion\n                            |\n                            v\n             NORMAL / WATCH / DEGRADED / CRITICAL\n                            |\n             +--------------+--------------+\n             |                             |\n             v                             v\n       FastAPI response               FleetService\n             |                             |\n             v                             v\n         Frontend                  maintenance / what-if /\n                                   fleet availability\n```\n\n## Model scope\n\nThe C-MAPSS-trained models are currently applied only to ENGINE. Other components remain synthetic/decision-layer state until component-specific training data and models exist.\n\n## Runtime behavior\n\nThe backend looks for local artifacts under models/cmapss/:\n\n- fd001_lstm_rul.keras + metadata + scaler\n- fd001_tcn_rul.keras + metadata + scaler\n- fd001_rul.joblib baseline fallback\n- fd001_failure.joblib\n- fd001_isolation_forest.joblib\n\nThe selected RUL architecture is controlled by FLEETAVAIL_RUL_MODEL. The default is lstm; set it to tcn to use the TCN artifact.\n\nThe model directory can be changed with FLEETAVAIL_MODEL_DIR and the C-MAPSS root with FLEETAVAIL_CMAPSS_ROOT.\n\nWhen local FD001 data exists, the WebSocket demo replays actual C-MAPSS test telemetry to warm the model pipeline. Without the dataset, the backend falls back to generated C-MAPSS-shaped telemetry.\n\n## API contracts\n\n### GET /api/models\n\nReports which trained branches are loaded.\n\n### POST /api/predict\n\nAccepts aircraft_id, component, and telemetry. Telemetry supports sensor_1 through sensor_21 plus op_setting_1 through op_setting_3. Legacy egt_c, vibration_g, and oil_pressure_kpa aliases are also accepted for mapped sensors.\n\n### WS /ws/telemetry\n\nProduces telemetry events containing raw engine telemetry and the corresponding model/fusion result. This is the primary live dashboard path.\n\n## Deployment note\n\nGitHub Pages can host the static frontend but cannot run FastAPI or access local model files. For a separately deployed frontend, set window.FLEETAVAIL_API_BASE to the public backend origin. The backend must have the trained artifacts available on its filesystem or model volume.
